2一次「生成音频」的完整流程

generate(request) 主链路 —— 从点击按钮到落盘输出。

1

组装请求

UI → GenerationRequest：文本 · 提示词 · Seed · 空间模式 · 语速/音调 · calibration_text（情绪基调句）· emotion_instruct（情感指令）

2

查干声缓存（Dry Audio Cache）

缓存键 = 引擎 + 模型 + 文本 + 提示词 + seed + 参考音频 + 校准句 + 情感指令。命中 → 直接跳到第 5 步（换空间效果不重算 TTS）

3

路由：短文直出 / 长文锁定（详见下方放大图）

单块短文（≤400 字且未填情感指令）→ Qwen VoiceDesign 直出，不加载克隆模型（TTS_DIRECT_SINGLE_CHUNK=0 可关闭）；长文或填了情感指令 → 校准句（请求级 > 全局 TTS_VOICE_CALIBRATION_TEXT）→ 合成/复用校准 clip → 分块 → 逐块克隆 → 拼接（句间 300ms / 段间 700ms）

4

存入干声缓存

拼接后的干声写入 LRU 缓存（默认 32 条，DRY_AUDIO_CACHE_SIZE）

5

音频后处理（紫色链路）

语速 → 音调 → 空间渲染（单声道 / 双声道 / 虚拟脑后 / 静态 HRIR / 动态 HRIR）→ 归一化 → 写 outputs/（wav，可导出 mp3/ogg/flac）

6

返回结果

文件路径 · seed · 状态（含 chunks / speaker_lock / clip / dry_cache 信息）· clip_id（供收藏复现）

3生成路由：短文直出 vs 音色锁定链路（核心放大图）

单块短文直接 VoiceDesign 直出（快、省内存，但换文本即换声）；VoiceDesign 每次调用都会重新采样说话人 —— 长文用一条固定校准音频把音色钉死，再从它克隆全部正文。

⚡ 短文直出（单块 · 未填情感指令） 正文直接进 VoiceDesign（instruct=英文提示词）
不合成校准 clip、不加载克隆引擎
声音由（提示词, seed, 文本）共同采样 —— 换文本会换声
▼  以下为长文 / 填了情感指令时：
① Qwen VoiceDesign 造声 输入：英文提示词 + 校准句 + seed
输出：校准 clip（唯一一次直出）
→
② clip 落盘缓存 ~/.tts3d_studio/voices/
clip_id = hash(模型, 提示词, seed, 校准句)
不含情感指令 —— 换情绪不换声
→
③ 正文分块 按句/段边界切分
每块 ≤ 400 字
▼  每块克隆（引擎由 TTS_CLONE_ENGINE 决定）
Qwen3-TTS Base Clone 默认无情感通道
  • 同族 ICL 克隆：ref = 校准 clip + ref_text = 校准句
  • 音色传得牢，情感只渗透一部分
  • 适用：未填情感指令时的默认引擎
CosyVoice2-0.5B 填情感指令即自动启用
  • inference_instruct2(正文, 情感指令<|endofprompt|>, 校准wav)
  • 同一音色 + 逐块可变情绪 → 长文有起伏
  • 独立 venv 长驻子进程（行式 JSON 协议），CPU 推理
  • 实验数据：中性克隆 F0 偏差 0.1Hz；情感指令 +9~21Hz
试听 / 收藏不受情感影响：参考音试听直接播校准 clip；收藏保存 prompt + 情绪基调句 + seed + clip_id + 空间参数，应用时全量回填 —— 同一把声音完整复现。

6关键环境变量

变量作用
TTS_CLONE_ENGINE克隆引擎：auto（默认，填情感指令→CosyVoice2）/ qwen3_base / cosyvoice2
TTS_DIRECT_SINGLE_CHUNK单块短文直出 VoiceDesign（默认开）；0 恢复短文也走音色锁定
TTS_VOICE_CALIBRATION_TEXT全局校准句；UI「情绪基调句」留空时回退到它
TTS_SPEAKER_REF_MAX_CHARS校准句最大字数（默认 60）；0 关闭音色锁定
MAX_TTS_CHUNK_CHARS长文本每块最大字符数（默认 400）
COSYVOICE_REPO_DIR / COSYVOICE_MODEL_DIRCosyVoice2 源码与权重路径（默认指向 tools/cosyvoice_experiment）
TTS_COSYVOICE_PYTHON运行 CosyVoice2 worker 的独立 venv 解释器
